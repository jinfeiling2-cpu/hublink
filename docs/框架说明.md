# Hublink 框架说明

这个站用来让读者认识一个人。它回答的是不同的问题：这个人是谁、哪几件工作最重、一个项目里面怎样搭起来又怎样运行、一段经历引出了什么、某个账号里哪几条内容值得放进对这个人的理解。

外部仓库和社交平台是出口。精确简介、角色、结果、说明，以及架构和运行，写在这张图里。GitHub 能提供的是核对用的薄信息和一份不覆盖正文的草稿。小红书目前不能把笔记拉进来。

## 读者停在哪一层

每个节点有五层。阅览决定展示到哪一层，不另抄一份内容。某一层可以空着。

| 层 | 读者得到什么 |
| --- | --- |
| 摆放 | 标题、类型、时间、规模、重要性、亲疏、公开或个人。排序和三维网格只用这些。 |
| 识别 | 一两句精确简介，加上角色和结果。简历式浏览停在这里仍然完整。 |
| 说明 | 问题、做法、结果，或一段经历里的情境与实际工作。 |
| 内部 | 沿着连接展开的结构、运行、决策或阶段。 |
| 出口 | 主链接和深链。形成内部图景之后，从这里去看原文。 |

项目会用满五层。以图片为主的社交账号往往只有识别层和出口。一条重要笔记可以有说明层，并用连接指向它记录的项目。

## 节点类型

类型是登记，不是写死的页面。每种类型声明自己使用哪些层、允许哪些向下的连接。当前登记：

| 类型 | 用途 |
| --- | --- |
| 人 | 这张图的主体 |
| 方向 | 持续追问的问题。项目用「体现」连过来 |
| 项目 | 一件工作。内部展开架构和运行，出口指向仓库 |
| 架构部分 | 一块职责。出口可以落到仓库里的具体路径 |
| 运行步骤 | 事情运转时的一步，按序号相连 |
| 决策 | 一个选择及其后果 |
| 经历 | 一段有时间范围的工作或学习 |
| 经历片段 | 经历中的一次转折、发布或职责 |
| 社交账号 | 某个平台上的身份 |
| 条目 | 被选中的一条笔记、文章或发言 |
| 照片 | 条目下的一张图 |
| 组织 | 经历所在的机构或团队 |
| 协作者 | 一起完成工作的人 |
| 能力 | 工作或经历所能证明的东西 |

以后增加「谈话」或「论文」，是在 `src/domain/registry.ts` 加一种类型。

## 连接

连接有方向、有类型。它表示读者的下一个问题。任一端不是公开节点时，这条线不会进入公开页。

**组成**：包含、实现、依赖、供给、下一步。架构图和运行方式靠这些走。项目包含架构部分和运行步骤；步骤之间用「下一步」，并按序号排列。

**证据**：体现、证明、产出、记录。项目体现方向，证明能力；经历产出项目；条目记录项目或经历。

**历程**：发生于、所属、与…一起、引出。引出是因果，不是日历上的先后。

**来源**：来源。只有外部对象本身也是图里的节点时才用这条边。普通网址放在出口字段上。

## 维度

两类，都登记在同一处。

**度量**可以当排序键，也可以当三维网格的轴：时间、规模、重要性、亲疏、联系。联系由连线数量算出，其余写在节点上。规模和重要性由你判断，不从星标换算。没有填写时间的节点，在按时间排序时放在最后；在三维网格里靠在起点。

**类别**用来筛选和分组：活动种类（制作、研究、写作、组织、教学）、成果形态（产品、工具、系统、文本、谈话）、范围（个人、团队、机构、公开）、所处位置（主导、参与、独立）。一个节点可以同时落在几类上。

状态是节点上的单独字段：探索中、已发布、维护中、已结束。

## 阅览框架

每种阅览登记三件事：它回答的问题、使用哪一种排法、这种排法的配置。排法目前有五种：

| 排法 | 行为 |
| --- | --- |
| 节点图 | 力导向的圆和线。同一支用同一颜色，枢纽更大，名字写在大圆里面。点选后只亮出直接相连的点。 |
| 固定版式 | 「十几秒印象」：人取亲疏最高的一个，方向取亲疏前三，项目取重要性前三，经历取最近的四段。只用识别层。 |
| 排序 | 按时间、重要性、规模或联系排列。按活动种类时，再按类别分组。 |
| 三维网格 | 默认时间 × 重要性 × 亲疏。读者可以改三根轴，并拖动旋转。 |
| 沿连接深入 | 从项目、经历或社交账号出发，只沿登记允许的连接向前走。 |

公开页永远先去掉个人节点，再把剩下的图交给阅览。所以印象、排序和深入不会把个人草稿算进去。

新的读法优先加一条阅览登记。只有出现现有排法表达不了的视觉时，才增加新的渲染器。

## 公开与个人

可见性写在节点上，由后台切换。

- 公开接口 `GET /api/graph` 和所有阅读页只返回公开节点，以及两端都公开的连线。
- 手写节点默认个人。
- GitHub：公开仓库新建时默认公开，私有仓库默认个人。再次拉取只更新快照，不改写简介、说明、角色、结果和可见性。
- 小红书账号由你在表单里选择，默认个人。平台上是否公开，不能在这里自动得知。

把一个私有仓库改成公开，只展示你留在节点上的字段。仓库地址对普通访客通常仍然打不开，所以不要把私有目录树当成公开页的正文。

## 来源能拉什么

**GitHub** 使用官方接口。可以拉取名称、简介、语言、话题、许可证、最近推送时间、星标、复刻数、主页、一段 README 摘录和根目录。摘录和目录只留在后台的快照里，不写入说明层，也不进入公开接口。私有仓库需要服务器上的 `GITHUB_TOKEN`，权限用内容只读即可。

拉取新建项目节点时，标题用仓库名，识别层用仓库简介，说明层留空。角色、结果、架构和运行仍然要你写，并用连接拆开。

**小红书** 官方接口尚未开放笔记读取，这一版不拉取笔记和图片。能做的是登记主页链接和一段你写的说明。需要深化的笔记，另建「条目」节点，写上它主张什么，再连到相关项目或经历，出口放原文链接。

没有稳定接口的其他平台，用手动节点和出口链接。

## 代码对应

| 位置 | 职责 |
| --- | --- |
| `src/domain/registry.ts` | 层、类型、连接、维度、阅览、来源 |
| `src/domain/graph.ts` | 公开过滤、排序、印象取舍、深入、坐标、来源合并 |
| `src/domain/graph.test.ts` | 上述规则 |
| `src/content/hublink.ts` | 第一个项目「Hublink」的内部图 |
| `src/db/store.ts` | SQLite 中的节点、连线和类别 |
| `src/lib/github.ts` | GitHub 快照 |
| `src/app/page.tsx` | 阅读入口 |
| `src/app/view/[id]/page.tsx` | 节点图和其余排法 |
| `src/app/node/[id]/page.tsx` | 一个公开节点的各层 |
| `src/app/framework/page.tsx` | 把登记展示出来 |
| `src/app/admin/` | 登录、节点、连线、来源 |
| `src/app/api/graph/route.ts` | 公开图 |

数据库文件在 `data/hublink.sqlite`，不提交。换机器或换托管时，这份文件就是图；代码仓库里的登记是框架，不是你的履历。

第一次打开时，图里会有一个公开项目「Hublink」。它用自己的内部点讲这个网站如何搭建、一次访问如何走，并留出一支「留白」。后台改过的字会保留。某个点被删掉之后，下次启动才会按原文把这个编号补回。

## 这一版没有做的

- 除了讲解本网站的这一套点，个人履历和其他作品还没有写。新内容挂到「留白」，或另建项目。
- 在后台里新增一种阅览或一种节点类型。现在的扩展点是登记表。
- 把站点部署成永久公开网址。当前是可运行的 Next.js 应用，图在服务器侧的 SQLite 里。静态的 GitHub Pages 不能保存这种写入。
- 小红书笔记同步。等官方开放读取之后，可以接上同一种来源合并，不必改节点模型。
