# 资料收集箱使用说明

项目根目录下的 `资料收集箱/` 用来收集后续讨论的个人原始材料。请先把文件放在对应目录；现阶段不要求它们符合统一格式，也不要求信息完整。简历、个人规划、零散概述和粗略想法都可以作为后续梳理的起点。

## 文件夹分类

```text
资料收集箱/
├── 01-简历与履历/
├── 02-个人规划/
├── 03-项目与经历概述/
├── 04-目标与关注问题/
└── 05-其他材料/
    ├── 游戏构思/
    ├── 世界观创作/
    └── 思想讨论/
```

资料一时不知道放哪里时，先放进 `05-其他材料/` 即可。游戏构思、世界观和长期讨论可以放入相应子目录；子目录表示材料用途，不表示公开程度。可以直接复制原文件，也可以放 PDF、Word、Markdown、纯文本或图片。文件名可加日期和来源，例如 `2026-10-22-当前简历.pdf`、`个人规划-草稿.md`；不用为了整理而提前重写原文。

## 这些资料之后怎么用

后续阅读时先保留原文，再另行整理结论和问题。每条整理内容会区分：原文明确写出的事实、你补充的解释、从多份材料中归纳出的判断、还需要你确认的内容。

低颗粒度或比较泛的资料也有价值。它们可以先帮助发现未来可能需要的阅读视图，例如：

- 简历概览：身份、方向、代表项目与经历。
- 时间线：经历、项目、阶段变化和重要节点。
- 规划视图：目标、优先级、依赖关系和仍待决定的问题。
- 项目 / 经历阅读：背景、角色、过程、结果、证据和反思。
- 学习视图：已经掌握的内容、疑问、练习和待验证的认识。

先从材料中找出稳定、反复出现的信息，再决定这些视图和字段是否适合进入正式图谱；不要让第一份简历或规划限定最终框架。

## 隐私与版本

`资料收集箱/` 已加入 Git 忽略规则。放在这里的个人原始材料不会被 Git 跟踪，也不会因为提交项目代码而进入公开仓库或网站。后续只有经过你确认适合公开的整理结果，才考虑转入正式内容。

请不要把密码、证件号码、完整住址、私人联系方式或不希望讨论的第三方个人信息放入资料。若原始文件带有这些信息，提供前可以先删去或遮盖。

原始材料尽量保持不变。需要编辑时复制一份并在文件名注明“整理稿”或日期，方便回到来源核对。

## 当前阶段

本目录只负责收集和理解材料，暂不自动导入数据库、不自动发布，也不据此立即重构图谱。待有足够的项目、经历和产出资料后，再根据真实材料验证简历生成、深度阅读和 AI 读取，并进行第二波调整。

本轮材料整理结果见 [资料收集箱整理索引](资料收集箱整理索引.md)、[资料收集箱分析与框架映射](资料收集箱分析与框架映射.md) 和 [材料分层与公开发布流程](材料分层与公开发布流程.md)。原始文件按五类目录及少量子目录归档，文件名和内容保持不变；索引只记录分类、来源状态、隐私和后续阅读方式。
