# 公开内容候选清单

记录时间：2026-10-26

这是一份编辑清单，不是公开发布结果。`公开候选`表示已经值得整理成面向访客的版本，但仍要经过本人核对；它不会自动出现在网站、API 或 GitHub 仓库中。原始材料继续留在被忽略的 `资料收集箱/` 中。

## 状态词

| 状态 | 含义 | 是否进入公开站 |
| --- | --- | --- |
| `公开候选` | 有明确的公开用途，正在做脱敏、核对和改写 | 否，完成核对后才发布 |
| `个人` | 只用于本人思考、学习、证据保存或未公开创作 | 否 |
| `待决定` | 已经可以整理出独立内容，但公开范围和表达方式还需要本人决定 | 否 |
| `已公开` | 已经写成公开条目，并由本人确认发布 | 是 |
| `归档` | 保留历史来源，不作为当前阅读入口 | 否 |

这些状态描述的是发布过程。项目的“构思中、原型、测试、已发布”等描述另属于工作阶段；一份构思可以公开其概念摘要，也可以仍然是个人资料，不能用一个字段同时表达两件事。

## 第一批实际发布对象

第一批不应把所有原件搬到网页。建议只做下面三个整理结果来验证流程：

1. 一版去除不必要私人联系方式、并由本人核对的公开简历。
2. 一页公开研究简介，明确当前研究与远期计划的区别。
3. 一份个人创意档案，先以《怪谈模拟器》为例，展示“构思如何被拆成结构、流程和待验证问题”，不把它写成完成游戏。

这三份材料分别检验公开履历、公开规划和私人创意的边界。通过核对后，再决定是否把公开简历和研究简介创建为 Hublink 节点；创意档案是否转成公开节点，仍由本人单独选择。

## 从清单到 Hublink 的暂定规则

- 只有 `已公开` 的整理结果才进入公开节点、公开连线、公开 API 和 AI 公开资料包。
- `公开候选`、`待决定` 和 `个人` 继续留在本地整理区，不因被写进这份清单而公开。
- 原件、证明附件、私人对话和未采纳的 AI 建议默认不放进公开节点正文。
- 一个公开的项目节点可以只包含公开摘要；它的私人设定、证据和学习记录应拆到个人文件或个人节点。
- “有公开摘要”不等于“项目已经完成”；网页必须同时显示实际工作阶段和已有证据。

目前数据库只提供节点级 `public` / `personal`，所以发布时先按可独立阅读的内容拆分节点和整理稿。等多种材料实际走完这条流程后，再决定是否需要 `review`、`archived` 或区段级可见性。
