# 资料收集箱分析与框架映射

整理时间：2026-10-26

这份文档回答两个问题：这些材料共同暴露了什么内容结构，以及它们应该怎样进入 Hublink 才不会被自动拼成一段过度漂亮、却无法核对的个人叙事。这里的归纳是工作假设，不是对个人身份的最终定义。材料类别、完成阶段、来源和发布范围需分别判断，详见[材料分层与公开发布流程](材料分层与公开发布流程.md)。

## 一、材料中反复出现的结构

### 1. 从知识到行动，中间有一串不能跳过的条件

研究策略把问题拆为情境、行动、状态、结果、干预和证据；《虾仁模拟器》把“知道技术”拆成概念、原理、实验、工程和产业；《怪谈模拟器》把观察拆为真实事件、人物感知、记录和交班；Hublink 自己也把目标拆成页面、领域规则、存储、后台和来源同步。

这说明一个有用的共同结构是：

```text
问题 / 情境
  -> 可执行行动
  -> 中间状态与约束
  -> 结果
  -> 证据与反馈
  -> 下一次决定
```

它可以成为项目深读的通用骨架，但不能被误读成“所有项目都必须是同一种算法流水线”。小说和思想文章可能使用同一骨架来解释主题，却不一定有可执行代码或实验结果。

### 2. 不可靠信息不是装饰，而是系统的一部分

《怪谈模拟器》关注规则是否有效、信息如何污染、不同角色知道什么以及怎样把可靠信息交给下一班。《尔虞我诈江湖模拟器》关注侦察、伪装、声誉、信任和反侦察。《光锥》里大量讨论也在区分事实、解释、意识形态和无法证伪的宏大判断。

对 Hublink 的直接启示是：来源、作者、置信度和状态必须比“标签”更重要。一个漂亮的关系图不能替读者判断一句话是原始事实、本人解释、AI 建议还是系统推断。

### 3. 系统会产生副作用，改变问题本身

《虾仁模拟器》里技术会受到工艺、组织、利益集团和历史惯性的反作用；《五方承脉》与《七件武器》把力量、身体、组织和代价连在一起；研究策略也强调干预必须受物理、社会、权限和伦理约束。它们都不把“找到一个好方案”当作终点。

因此，项目页不能只有目标和成功结果，还需要“限制、代价、失败条件和未解决问题”。这比继续增加视觉维度更能帮助读者理解工作方式。

### 4. 传承和连续性是重要主题

《怪谈模拟器》的核心是角色交班和把有限知识传给后来者；研究策略设计了 Alignment Core、Reality Snapshot 和 Project Alignment Packet；远景附录讨论认知记录和数字遗产；Hublink 想让人、访客和 AI 共享一套可修正资料。

这可以支持 Hublink 的“共同学习”阅读方式，但必须把它定义为有授权、可撤回、可审查的记录系统，不能宣称它保存了一个人的意识或完整内在。

### 5. 结构化拆解本身就是一种工作能力

研究策略有工作包、论文分工、基线、证据阶梯和四周行动；《怪谈模拟器》有 MVP、逐日路线、数据结构、系统边界和验收场景；《混沌摆》则把同一物理核心分成闯关、星图和长期助眠三种体验。

这说明未来项目档案应展示“如何从一个想法收束到可验证的最小切片”，而不是只展示最终名字和一张概念图。

## 二、需要坚持的内容分层

每个重要判断都建议存成下面五种状态之一，并保留来源：

| 内容状态 | 可以怎样写 | 不能怎样写 |
| --- | --- | --- |
| 已核对事实 | “简历记录某论文为第一作者、在审；待本人确认当前状态。” | 直接写成已发表。 |
| 本人明确判断 | “本人将博士基本盘表述为……” | 把 AI 的改写当成原话。 |
| 当前计划 | “当前优先准备……” | 写成已经完成的研究成果。 |
| AI / 他人建议 | “讨论中提出了……，待本人接受或否决。” | 放进正典或简历事实。 |
| 开放问题 / 推断 | “从多份材料暂时观察到……，需要确认。” | 以心理诊断或身份结论呈现。 |

创作材料还应增加“正典状态”：原始设定、已接受设定、候选建议、废弃或过时。研究材料则应增加“研究承诺层级”：博士承诺、当前任务、长期议程、元层基础设施、推测远景。

## 三、对当前 Hublink 模型的映射

当前模型已经有 `person`、`direction`、`goal`、`concept`、`project`、`experience`、`part`、`flow`、`decision`、`entry`、`organization`、`capacity` 等节点类型，以及“包含、依赖、产出、体现、证明、发生于、记录、主题关联、服务于、为工作画像提供材料”等连接。`concept` 用来承接跨项目的思路要点，`part` 表示项目内部的问题、机制、阶段、决策或叙事单元，不等于代码目录。它足以先做内容试验，但不能自动解决材料的来源与作者归属。

目前新增了一条可回溯的阅读链：项目先拆成项目内部分支，再通过思路要点连接到方向或目标；目标、方向和项目可以共同为“暂定工作画像”提供材料。这里的连接是整理假设，理由和人工权重必须与节点一起阅读，不能当作心理测量或已经证明的因果关系。

| 材料对象 | 当前可用节点 / 连接 | 需要在内容层补足的说明 |
| --- | --- | --- |
| 教育与实习 | `experience`、`organization`、`episode`；用“发生于 / 产出 / 证明”连接 | 时间、实际职责、外部证明、公开程度；证明文件不能等于成果叙述 |
| 论文与研究项目 | `project`、`direction`、`capacity`、`decision`；用“体现 / 证明 / 包含”连接 | 作者角色、论文状态、研究问题、方法、证据和限制 |
| 研究战略 | `direction`、`project`、`decision`、`entry` | 基本盘、当前任务、长期议程和推测远景必须分开 |
| 游戏策划 | `project`、`part`、`flow`、`decision` | 概念、策划、原型、测试、发布等状态；AI 扩写和本人决定分开 |
| 小说 / 世界观 | `project`、`part`、`entry`、`decision` | 设定版本、正典状态、建议来源、空白区域和读者入口 |
| 思想讨论 | `entry`、`direction`、`decision`、`source`（未来可增加） | 论题、论据、反例、事实核查、个人判断和助手回应不能混写 |
| 证书 / 代码 / 论文链接 | `source` 或出口链接 | 来源只能证明它实际能证明的范围，不自动证明个人贡献或影响 |

### 建议的内容附件，而不是马上新增数据库字段

第二波调整前，可以先在文档和案例卡中使用以下最小元数据：

```text
内容状态：confirmed / self-reported / planned / suggested / inferred / open
作者来源：本人 / 合作者 / AI / 外部文件 / 未知
证据等级：代码 / 外部证明 / 论文或链接 / 自述 / 尚无证据
公开状态：public / personal / draft / archived
更新时间：YYYY-MM-DD
需要确认：一到三条具体问题
```

这些字段先通过整理稿验证是否真的有用。等至少有一份简历、一项软件项目、一项创作项目和一份思想文章都走过流程后，再决定是否写入正式 schema。

## 四、建议建立的阅读方式

### 1. 简历概览

默认只显示已经确认或明确标注为自述的身份、方向、教育、代表项目、论文和经历。它必须优先使用人工选择的代表项目，不从连接数量自动推断“最重要”。每条成果显示角色和状态，必要时显示证据入口。

### 2. AI 资料包

提供稳定的结构化出口，至少按对象输出标题、类型、时间、角色、摘要、结果、证据、来源状态、可见性和相关对象。它应该让 AI 很快知道哪些内容可以引用，哪些需要追问，而不是让 AI 从图形位置猜含义。

### 3. 项目深读

统一提供“问题—结构—运行—决定—结果—证据—限制—个人理解”路径。对于研究项目，可把“结构”换成变量、模型和实验；对于游戏策划，可换成玩法循环、状态、内容和验收；对于小说，可换成世界观、人物、冲突和版本。

### 4. 时间与变化

显示教育、经历、论文、项目和设定版本的变化。研究战略中的时间不能只作为排序，它还要表达“当前承诺”和“远期议程”的变化；创作材料要能回看某个设定何时由建议变成正典。

### 5. 证据与不确定性

读者可以打开一条结论，看到它的来源、证据范围和未解决问题。推荐采用：

```text
结论：当前原型实现公开节点过滤
证据：公开查询、领域过滤函数及测试
状态：代码确认
范围：证明功能存在，不证明已有真实访客使用
```

### 6. 共同学习

把“我还不懂什么、AI 可能误解什么、下一次怎么验证”作为一等内容。Hublink 当前已有学习问题，可以将它扩展到每个项目，但不应把学习记录伪装成项目成果。

## 五、每类材料的下一步处理

### 履历材料

先做字段核对表：教育时间、研究方向、每篇论文的作者角色和状态、每个项目的实际贡献、可公开链接、可公开联系方式。实习证明只用来核对经历存在和文件信息，职责与结果仍由本人补充。

### 研究战略

抽出四张卡：`当前博士基本盘`、`正在推进的项目`、`长期研究议程`、`推测性远景`。每张卡都注明它能否进入简历、能否公开、AI 可以怎样使用。研究策略本身更适合作为内部对齐文档，不应整篇暴露给普通访客。

### 游戏与创作材料

每个创意档案只先写一页：原始问题、核心体验、系统拆解、当前阶段、已有证据、AI 参与部分、下一步最小验证。没有代码或试玩时，结果字段写“尚无实现证据”，不要填写想象中的用户反馈。是否公开摘要与工作阶段是两件事：可以公开一份构思说明，但不能把构思写成已完成项目；也可以暂时全部留在个人区。

《怪谈模拟器》可以先做一个示范，因为它有清晰的规则、模拟层、感知层、记录层和验收场景；《混沌摆》可以检验同一核心如何产生三种阅读 / 产品形态；《虾仁模拟器》可以检验“概念—原理—工艺—组织—制度”的层级；《尔虞我诈江湖模拟器》可以检验多主体信息和信任关系。

### 长篇世界观与思想档案

按“问题 / 原始片段 / 后续回应 / 已接受结论 / 反例 / 待核查”拆分，不要直接把几百页对话作为一个节点。若未来公开，先选择一个完整、可独立阅读的条目，而不是公开整个私人档案。

## 六、哪些内容能形成个人简介，哪些还不能

### 可以形成的初步主线

目前材料支持一个谨慎的工作表述：你正在香港大学进行建成环境、人类行为与 AI 交叉研究，关注动态、受约束环境中的决策理解、干预设计和可验证反馈；同时持续构思游戏、叙事和社会系统，把规则、信息、约束、代价和知识传承作为重要设计问题。

这只是整理假设。研究部分有简历和研究战略支撑；创作部分目前主要有概念文档，不能与已完成作品并列。

### 还需要本人确认的部分

- “持续构思”是否是你愿意公开的身份描述，还是只留在个人档案？
- 哪些游戏或小说已经有代码、原型、章节、读者或试玩证据？
- Hublink、研究项目和创作设想之间是方法迁移关系，还是仅仅同时存在？
- 哪些 AI 建议你已经接受，哪些只是保留作讨论材料？
- 你希望公开简历突出研究、工程、创作，还是以研究为主并提供创作入口？

## 七、暂缓的框架改动

这批材料确实暴露出未来可能需要的“来源 / 置信度 / 作者 / 版本 / 研究承诺层级”字段，但现在不直接改 schema，理由是：

1. 当前收集箱仍以混合文档为主，尚未经过本人逐项核对。
2. 过早新增字段会把某一种整理方法误认为最终数据模型。
3. 现有 Hublink 的项目、经历、决定、证据和学习路径已经足以做第一轮案例卡。
4. 等简历、Hublink、一个创意项目和一个思想条目都被整理后，再看哪些字段反复出现。

第二波调整的判断顺序应是：先验证简历准确性，再验证项目深读，再验证 AI 资料出口，最后才调整图谱、三维坐标和视觉形式。
