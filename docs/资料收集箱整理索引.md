# 资料收集箱整理索引

整理时间：2026-10-26；按后续补充更新

这份索引记录当前 `资料收集箱/` 中已经读过的材料。原件按用途归档，不自动导入 Hublink。目录本身被 Git 忽略，因此原始个人资料不会进入公开仓库。创意材料后来确认属于构思和讨论档案，已从宽泛的“其他材料”目录整理到对应子目录；原始文件内容保持不变。

## 先看结论

这批材料已经足以验证一件事：Hublink 不能只把内容当作“节点 + 一段简介”。材料同时包含履历事实、研究计划、游戏与文学创作、哲学讨论、证据文件和大量 AI 参与的扩写。它们需要共同的来源与状态说明，但不能被压成一个统一的个人故事。材料类别、实际完成阶段、来源和发布范围必须分别记录。

当前最适合先做的工作是内容整理和简历核对，而不是第二次改数据库。简历和研究策略可作为公开简介与研究型简历的候选来源；游戏和创作材料目前是个人构思档案，不是已完成项目；实习证明可以作为个人证据，不能只凭文件名推断工作内容。项目简介可以日后公开，项目里的草稿和具体设定仍可保留在个人区。

## 分类规则

| 标记 | 含义 |
| --- | --- |
| `事实候选` | 原文直接陈述的个人经历、教育、论文、代码或外部文件事实；发布前仍需由本人核对。 |
| `当前计划` | 正在推进或明确安排中的方向、论文、工程任务；不能写成已完成成果。 |
| `创意候选` | 游戏、小说、世界观或方法设想；除非有成品和证据，否则状态应为探索中。 |
| `推测远景` | 哲学、文明或数字遗产层面的长期思考；不能自动进入简历。 |
| `AI 扩写` | 文本中明确由 Gemini、ChatGPT 或其他助手补出的部分，不能当作本人原始主张。 |
| `待确认` | 需要本人确认的作者归属、时间、角色、结果、证据或公开范围。 |

“AI 扩写”不等于没有价值。它可以作为设计候选、反例或讨论记录保存，但要和本人已经认可的内容分开。

## 按用途重新分组

### A. 可以先用于简历验证

1. `个人简历-02.docx`：作为候选内容源，不作为无需核对的最终简历。
2. `@_03_金飞凌_研究定位与发展路线梳理_202608_V3.docx`：用于校准研究方向、论文之间的边界和当前优先级。
3. `科大讯飞实习证明-compress.pdf`：作为私有证据，等待与简历中的经历条目对应。

这一组可以先生成三份东西：普通读者能读的简历、给 AI 的结构化履历包、带来源和状态的核对表。简历里必须区分“已发表 / 在审 / 参与 / 第一作者 / 通讯作者”等原文状态，不能用统一的“完成”替代。

### B. 创意构思档案，暂不能写成完成成果

`怪谈模拟器 - V2.docx`、`虾仁模拟器.docx`、`小游戏-混沌摆.txt`、`尔虞我诈江湖模拟器.docx` 都能支持对玩法问题和设计思路的梳理，但目前材料证明的是构思与策划。若没有代码、试玩、测试或发布证据，不得写成已完成游戏、已验证产品或有用户反馈的成果。它们可以留在个人档案，也可以在未来由本人选择一份公开摘要；公开摘要不要求公开原始策划。

其中《怪谈模拟器》最适合成为第二个 Hublink 案例，因为它已经自然分成目标、规则、状态、感知、记录、交班和验收；但它仍需要本人确认哪些设计是自己提出、哪些接受了 AI 建议，以及是否实际制作过原型。

### C. 适合成为创作档案

`七件武器系列_框架梳理版_v2(1).docx` 与 `五方承脉.docx` 应按“原始设定、整理建议、待定空位、版本变化”保存。读者可以查看世界观和结构，但不能把 AI 补全的角色、历史或剧情当成作者已经决定的正典。

### D. 适合成为思想与学习档案

`光锥.docx` 和远景附录适合支持个人总结、AI 深读和共同学习，不适合直接放到默认简历。它们应把一个讨论拆成：问题、本人原始判断、外部事实、助手解释、暂时结论、反例和仍未解决的问题。

## 当前不应直接公开的内容

- 简历中的电话、邮箱和其他完整联系方式；公开版应由本人另行选择字段。
- 实习证明原件及其中可能包含的身份信息。
- 研究战略底稿中的个人现实约束、未公开论文计划和协作协议细节。
- 尚未发布的小说、世界观和游戏草稿。
- `光锥` 中涉及私人讨论、未经核查的社会判断和助手生成的强结论。

公开站只接收经过本人确认的“整理稿”或结构化条目，不直接读取收集箱原件。公开状态按可独立阅读的内容分别决定；项目整体公开不会自动公开其私人子项。当前后台只有节点级可见性，混合公开和个人内容时应拆成不同文件或节点。

## 目前能支持什么

### 已有足够材料支持

- 一版以香港大学博士研究、建筑环境中的人类行为与 AI 交叉研究为主轴的研究型简历草稿。
- 论文、研究项目、技能和教育经历的初步结构化清单。
- 研究方向的当前承诺 / 长期议程 / 推测远景三层区分。
- Hublink 的“项目结构图 + 运行图 + 证据 + 学习问题”组织方法在不同材料上的初步检验。
- 一组可供访客或 AI 深读的创作项目候选和思想档案候选。

### 还不能声称已经支持

- 已经完成或发布了这些游戏、小说和世界观项目。
- AI 已经准确理解个人内在、价值或长期身份。
- 所有简历中的角色、成果和论文状态都已由外部材料核对。
- 这些材料可以直接变成公开网页；隐私、作者归属和发布范围仍需逐项确认。

## 下一次整理顺序

1. 先核对简历中的教育、论文、项目角色、时间和成果状态。
2. 再把研究战略拆成“博士基本盘、当前任务、长期议程、元层协作、推测远景”。
3. 为每个创意项目建立一页案例卡，只记录原始想法、已经接受的设计、AI 建议、当前状态和下一步验证。
4. 从《怪谈模拟器》选择一个个人学习用案例，分别写结构图、运行图和设计决策记录；除非另行确认公开范围，不进入公开内容。
5. 最后才根据这些案例检查 Hublink 是否需要增加字段、关系或阅读方式。
